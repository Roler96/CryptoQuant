# CRDR 日内策略研究设计

- 日期：2026-08-03
- 研究标签：`crypto-cross-sectional-residual-dispersion-reversion-v1`
- 状态：冻结设计；任何结果计算必须晚于本文件提交
- 目标：判断跨币种异常残差分化在 6 小时内是否均值回归，并在保守交易成本后形成可交易的市场中性日内策略

## 1. 方向选择

本轮比较了三个方向：

1. **跨币种残差冲击反转**：样本量大、可以市场中性、与仓库既往单币方向研究正交；主要风险是换手成本。
2. **波动压缩后的日内突破**：事件稀疏且换手较低，但与已经研究过的 VCSE、SIC 和 BIC 冲击延续家族过近。
3. **日内相对强弱轮动**：只做现货即可，但难以区分选币能力与加密市场 beta。

选择第一种，并命名为 **CRDR（Cross-sectional Residual Dispersion Reversion）**。它检验的是横截面相对价值，不再预测单一币种下一根 bar 的绝对方向。

## 2. 可证伪假说

主假说：剔除 BTC 同期市场因子后，主流山寨币 6 小时收益的横截面离散度若进入自身过去 90 天的高分位，极端赢家和输家包含暂时性流动性冲击；未来 6 小时中，输家相对反弹、赢家相对回落。

反证条件包括：

- 反转组合在主成本后不盈利；
- 收益仅来自做多腿或做空腿；
- 不做 BTC 残差化的原始收益反转不劣于主版本；
- 机械反向的延续组合不弱于反转组合；
- 收益集中于单一日历段、单一事件或孤立参数点。

## 3. 数据契约

### 3.1 时间边界

- 原始数据：`data/cq.db` 中的 OKX 1h OHLCV。
- 读取窗口：`[2021-01-01 00:00 UTC, 2025-06-01 00:00 UTC)`。
- `2025-06-01` 之后的既定验证窗口不读取、不计算、不用于调参。
- 由于 beta 和离散度阈值需要因果热身，首个可交易时点预计不早于 2021-05-01；实际首点由完整窗口决定，不手工补齐。

### 3.2 标的

BTC 永续只作为市场因子：

- `BTC-USDT-SWAP`

可交易横截面固定为九个永续：

- `ETH-USDT-SWAP`
- `DOGE-USDT-SWAP`
- `SOL-USDT-SWAP`
- `XRP-USDT-SWAP`
- `ADA-USDT-SWAP`
- `AVAX-USDT-SWAP`

BNB 因 2022 年末才开始覆盖、ASTER 因 2025 年才上市而排除。研究过程中不得按结果增删标的。

- 每个决策只使用当时已经闭合的 bar；代码必须通过 prefix-invariance 测试。

## 4. 冻结信号

设决策检查点为每日 `00:00`、`08:00`、`16:00 UTC` 的 `c`。检查点 `c` 只读取截至 `c` 刚刚闭合的数据。

### 4.1 市场 beta

对每个可交易标的 `i`，用信号窗之前 30 天的 720 个完整 1h 对数收益估计：

```text
beta_i(c) = Cov(r_i, r_BTC) / Var(r_BTC)
window = [c - 726h, c - 6h)
```

beta 使用样本协方差和样本方差，不截尾、不裁剪；BTC 方差为零或样本不足时该决策作废。beta 窗刻意排除当前 6 小时冲击，避免冲击本身改写基准暴露。

### 4.2 残差收益与离散度

```text
R_i(c)   = log(close_i(c) / close_i(c - 6h))
R_BTC(c) = log(close_BTC(c) / close_BTC(c - 6h))
epsilon_i(c) = R_i(c) - beta_i(c) * R_BTC(c)
D(c) = percentile_90(epsilon(c)) - percentile_10(epsilon(c))
```

这里的 `close(c)` 指 `c` 时刻刚闭合的 1h bar 的收盘价，而不是从 `c` 开始的新 bar 的未来收盘价。
横截面 percentile 和时间序列 quantile 都使用 NumPy 的线性插值法 `method="linear"`。

### 4.3 因果离散度闸门

只在 `D(c)` 严格大于过去 90 个自然日内、同样三个 UTC 检查点得到的历史离散度的 80% 分位时交易：

```text
D(c) > quantile({D(s): c - 90d <= s < c}, 0.80)
```

当前 `D(c)` 不得进入自己的阈值。过去窗口至少要有 250 个有效检查点，否则该决策作废。

### 4.4 组合

- 按 `(epsilon_i(c), inst_id)` 升序排序；若第二/第三名或第七/第八名的残差完全相等，则跳过该事件，避免边界任意选币。
- 做多残差最低的两只，各 `+0.25` 权重。
- 做空残差最高的两只，各 `-0.25` 权重。
- 净敞口 `0`，总敞口 `1.0`，不加仓、不在持仓中再平衡。

## 5. 成交、持仓与成本

- 在检查点 `c` 计算信号。
- 入场：`c + 1h` 的 bar open。额外等待一小时，确保信号 bar 已完整闭合，并消除资金费结算与成交先后顺序的歧义。
- 离场：`c + 7h` 的 bar open，恰好持有 6 小时。
- 下一个检查点是 `c + 8h`，因此所有 episode 不重叠，episode 间至少空仓一小时。
- 00/08/16 UTC 是 OKX 常规资金费结算点；01→07、09→15、17→23 的持仓窗不跨常规结算点。历史动态结算频率无法由现有数据库完整验证，因此压力口径还要额外扣除每个 episode `5 bps` 的未知资金费惩罚；即使主策略通过，也只能进入 shadow 验证。
- 主成本：每次仓位变化每单位绝对权重 `15 bps`，即 `10 bps` 手续费加 `5 bps` 滑点。满总敞口的一次完整 episode 固定成本为 `30 bps` 的组合权益。
- 压力成本：每边 `25 bps` 加上述 `5 bps` episode 级资金费惩罚，一次完整 episode 共扣 `55 bps`。
- 每个 episode 入场时按当时账户权益确定四腿合约数量，持仓六小时内数量固定。逐小时 PnL 为 `entry_weight * (open_next - open_now) / entry_open`，不把权重每小时再平衡。入场和离场成本均按 episode 起始权益与初始总敞口计算，因此主成本严格为 `30 bps`、压力成本严格为 `55 bps`。
- 总收益、Sharpe 和 MaxDD 从包含空仓小时的连续权益曲线计算；小时收益为相邻权益点的简单收益，Sharpe 年化因子为 `sqrt(24 * 365)`。
- 不假设 maker 成交、盘口返佣、部分成交或零冲击。

## 6. 评估协议

### 6.1 日历稳定性

五个预声明评估段：

1. `[2021-05-01, 2022-01-01)`
2. `[2022-01-01, 2023-01-01)`
3. `[2023-01-01, 2024-01-01)`
4. `[2024-01-01, 2025-01-01)`
5. `[2025-01-01, 2025-06-01)`

每段独立报告净收益、Sharpe、MaxDD、episode 数、做多腿和做空腿贡献。不得合并相邻失败段或改用牛熊标签替代。

### 6.2 统计检验

- 主统计单位是 UTC 自然日的组合净收益；没有持仓的日保留零收益。
- 对去均值后的日收益执行 7 日 circular moving-block bootstrap，`B=5000`、`seed=0`。每次抽取连续 7 日的循环块直到达到原样本长度并截断；经验 p 值为
  `(bootstrap_mean >= observed_mean 的次数 + 1) / (B + 1)`，检验单侧零假设 `E[r_day] <= 0`。
- 对原始日收益执行同样的 block bootstrap。每次重抽样的年化收益定义为
  `prod(1 + r_day) ** (365 / N_days) - 1`，报告其 5% 分位。
- 另报告删除最佳单个 episode 后的总净收益。
- 本轮只有一个可晋级主候选；邻域和消融不参与择优，因此主检验 family size 为 1、`alpha=0.05`。

### 6.3 冻结邻域

只用于参数平原检查，不得替换主版本：

1. 残差信号 4h，持仓仍为 6h；
2. 残差信号 8h，持仓仍为 6h；
3. 持仓 4h，信号仍为 6h；
4. 持仓 5h，信号仍为 6h；
5. 离散度分位 70%；
6. 离散度分位 90%。

全部持仓邻域都在下一常规资金费点之前离场。

### 6.4 冻结消融与符号对照

- `raw-reversal`：不用 beta，直接按 6h 原始收益排名，其余不变。
- `ungated-residual-reversal`：不用离散度闸门，每个有效检查点都交易。
- `residual-continuation`：在完全相同事件上做多残差最高两只、做空最低两只。

这些结果只解释机制，不得作为失败后的替补策略。

## 7. 裁决

### 7.1 闸门

- **G0 完整性**：数据指纹已记录；对齐、prefix invariance、退化 bar、资金费避让和成本算术检查全部通过。
- **G1 经济性**：主成本总收益 `> 0`、年化 Sharpe `>= 0.75`、MaxDD `<= 25%`，且压力成本总收益 `> 0`。
- **G2 稳定性**：五段中至少四段净收益为正，六个冻结邻域中至少五个主成本收益为正。
- **G3 统计性**：block-bootstrap 单侧 `p <= 0.05`、年化收益 P5 `> 0`、删除最佳 episode 后总收益仍 `> 0`。
- **G4 双腿性**：做多腿和做空腿在各自分摊成本后累计收益都 `> 0`。
- **G5 样本量**：总 episode 数至少 200，且每个日历段至少 20。
- **G6 机制增量**：主版本 Sharpe 高于 `raw-reversal`，主版本每 episode 净均值高于 `residual-continuation`；`ungated` 只作解释，不设必须劣于主版本的门。

### 7.2 裁决语义

- `TRADEABLE_LEAD`：G0–G6 全过。只允许进入独立 holdout 或 shadow，不直接实盘。
- `REAL_BUT_SUBTHRESHOLD`：G0、G2、G3、G5、G6 通过，但 G1 或 G4 失败。统计结构可能存在，当前执行条件不可交易。
- `MECHANISM_UNSUPPORTED`：G0 通过，但 G2、G3 或 G6 失败。
- `CLOSED`：主成本总收益不为正，或样本量不足。
- `INVALID`：G0 任一项失败；必须修装置后按同一冻结规则重跑，不能改策略参数。

## 8. 软件边界

新增 `cq/research/crdr/`，按职责拆分：

- `data.py`：硬边界读取、指纹、公共时间网格和质量掩码；
- `signals.py`：beta、残差、离散度、因果阈值和选币；
- `backtest.py`：非重叠 episode、小时盯市、成本和腿贡献；
- `stats.py`：日收益 block bootstrap、日历段、邻域和裁决；
- `runner.py`：冻结参数编排和 JSON 报告；
- `cq/research/commands.py`：增加 `cq research crdr run`。

机器输出写到 `reports/research/crdr_v1.json`，人工结论写到 `docs/research/crypto-intraday/CRDR_RESULTS_2026-08-03.md`。只有裁决为 `TRADEABLE_LEAD` 才另行设计 `cq/strategy/` 中的可交易策略；研究 runner 本身不得进入 live 路径。

## 9. 测试与健全性

至少覆盖：

- 数据查询绝不越过 `2025-06-01`；
- 指纹先于过滤，缺 bar 不拼接；
- 合成序列验证 beta 与残差公式；
- beta 窗不含当前 6h 信号；
- 90 日分位严格排除当前离散度；
- 增加未来数据不改变既有信号（prefix invariance）；
- 排名边界 tie 时跳过；
- 信号、入场、离场分别位于 `c`、`c+1h`、`c+7h`；
- 持仓不跨 00/08/16 UTC 资金费点；
- 四腿权重净和为零、绝对和为一；
- 主成本和压力成本在手算小例子上精确一致；
- 同一 episode 不重叠，空仓小时保留零收益；
- continuation 对照准确反转权重；
- bootstrap 固定 seed 可复现；
- 任一完整性失败只能输出 `INVALID`。

## 10. 明确不做

- 不读取资金费率、OI、盘口、逐笔成交或 2025-06-01 后数据；
- 不训练机器学习模型，不搜索币种子集，不按结果选择 UTC 时段；
- 不把六个邻域或三个消融中表现最好的版本替换为主策略；
- 不在本轮实现 live 策略、下单或实盘资金配置；
- 不用主观牛熊分段解释失败结果。
